### 3. Priority Selection Logic — "Better Coverage" ✅
- **Logic locked in:**
  - If user selects "better coverage" → they want to LEAVE their current network
  - System eliminates current network providers
  - Example: Verizon user → system shows T-Mobile and AT&T options only
- **Secondary priority:** lower price

### 4. Priority Selection Logic — "Cheaper Price + New Phone"
- Most challenging combination to solve
- Martin suggested refurbished phones; Romeo noted lack of refurb-phone recommendation links
- Direction: sub-network with a new phone deal
- Surfacing this is complex due to inconsistent data

### 5. Complexity of New Phone Deals — Data Inconsistency
- No clear, consistent data on what constitutes a "new phone deal" on cheaper carriers
- Current assumption: most users on prepaid options use **BYOD** (Bring Your Own Device)

### 6. V1 Decision — Limit to 2 of 3 Variables
- **Decision:** for V1, use only **2 of 3 variables** (coverage, price, phone)
- Reason: surfacing new phone options requires ongoing data maintenance
- Romeo: phone IS a critical third variable, but eliminating it now is acceptable

### 7. "Better Coverage + New Phone" Logic
- Romeo's idea: if user selects "better coverage + new phone" → they're not price-sensitive
- Direct to a **post-paid plan** like T-Mobile's Magenta (offers phone credit)
- Scraping AT&T, Verizon, T-Mobile phone credit offers is easy, BUT offers change frequently → would require **daily manual maintenance**
- This is **too high-touch for V1**

### 8. Solution: Refurbished Phones via OEM Links
- **Decision:** for "new phone" requests in V1, redirect users to:
  - **Apple Certified Refurbished** / Apple trade-in
  - **Samsung Certified Refurbished**
- Avoids daily phone credit data updates
- Maintains **credibility** by sticking to certified OEM-direct sources
- Martin to check if Apple and Samsung have **affiliate programs** for transaction tracking

### 9. "Hassle-Free" vs. "Maximum Savings" — Clarification
- **Hassle-Free:**
  - Stay within same network, find cheaper price
  - **May include postpaid plans** initially
- **Maximum Savings:**
  - **STRICTLY prepaid options only**

### 10. Data Fields — Keep All, Use Subset for V1
- Jayesh asked about necessity of various data fields (hotspot capacity, offer columns, etc.)
- Martin's clarification:
  - Many columns added for **future potential use cases** (plan comparison, value normalization)
  - **V1 engine doesn't utilize most of them**
- **Decision:** keep all fields in DB; V1 logic only references the subset it needs

### 11. Streaming Data — Only Average Cable Cost Needed
- Martin confirmed: from streaming data, **only the "average cable cost"** is required for V1

### 12. Copy Edits on Landing Page Q&A
- Martin needs to make copy edits, specifically to the landing page's **Q&A section**
- Jayesh to send latest Figma link
