  - **3-line user:** $540 annual savings

### 3. ⚠️ Boost Mobile Limitation — No "Hassle-Free" Alternatives
- **Issue identified:** system **lacks cheaper alternatives for Boost Mobile customers**
- → No "hassle-free" savings can be surfaced for Boost users
- **Bigger pattern:** for **Boost, Cricket, Google Fi** users → system defaults to recommending **Mint Mobile** as ONLY "maximum" savings option
- _(⭐ Cross-day thread: this is the **always-Mint bias** Jayesh + Mark surfaced as a concern on May 21 — same root cause)_

### 4. UX Strategy for "No Wireless Savings Available"
- **Mark's call:** copy must be **engaging** — users shouldn't feel platform is useless if no plan available
- **Strategy:** pivot users to other categories (e.g. **internet services**) to maintain engagement

### 5. Automated Subscription Tracking — Proposed + SHELVED
- **Alexander proposed:** integrate **automatic subscription tracking** (similar to **Rocket Money**)
- Goal: let users manage savings without manual data entry burden
- **Mark's response:**
  - Acknowledges value
  - **NOT viable for MVP** due to:
    - **Regulatory implications** (PII handling)
    - **Cost implications**
- **Decision:** capture as **future roadmap item** — 🚫 SHELVED for MVP

### 6. ⭐ "Hassle-Free" vs "Maximum" Savings Logic Conflict — RESOLVED
- **Jayesh identified conflict:** in some scenarios, **"hassle-free" savings > calculated "maximum" savings**
- Asked: should max be shown in such cases?
- **Decision (Romeo + team consensus):**
  - If **maximum option = negative savings** → DO NOT show max
  - If **"hassle-free" option already optimal** → DO NOT show max
  - Instead: **congratulate user on being optimized** OR **pivot to internet/subscription suggestions**
- **Romeo's clarification:** if an **optimal plan exists within same carrier ecosystem** (e.g. **downgrading within Mint Mobile**) → that IS the maximum savings option

### 7. Internet Service Savings Logic
- Logic structure: **same as wireless**
- Compares user-selected plans (e.g. **Frontier**) against **average price points**
- Generates savings recommendations using delta

### 8. Dashboard Reporting Rule
- **Romeo's guidance:** savings should only count toward **global objective** once user **confirms they possess the specific service**
- Prevents inflated "potential savings" metrics from unconfirmed services
