# 2026-04-15 — Reyly Team Meeting

## Attendees
- Mark Gilmor
- Romeo Reyes
- Martin Lerda
- Jayesh Gohel

## Topics Discussed

### 1. Flex Offers API Integration — Documentation Gap
- **Flex Offers API documentation is insufficient** for direct integration
- Jayesh to prepare a document using **AI** to understand the process and workflow
- Integration requires admin panel setup managing:
  - Advertisers' IDs
  - Provider names
  - Commission rates
- **Monthly maintenance** required to keep provider data current

### 2. Provider Application Process
- One-time process: identify available providers in Flex Offers
- Missing providers (e.g., **Sling**) → apply → **1–3 days** for approval
- Monthly review needed to onboard new providers

### 3. Deep Linking & Product Catalog
- **Deep linking** will redirect users from app (e.g., "switch to Mint") → Flex Offers → final provider page
- Flex Offers contains **thousands of coupons** in product catalogs
- Team must determine which deals to surface on frontend
- Jayesh to explore product catalogs for gift card deals and products

### 4. Terminology Clarification — "Passes" vs. "Products/Coupons"
- **Reyly's "passes" / "perks"** (e.g., 20% off at Starbucks) = **"Products" / "Coupons"** in Flex Offers
- Admin panel will manage available coupons fetched from Flex Offers
- Team decides which ones to show to customers

### 5. Initial Launch Priority — Digital Passes ONLY
- **Decision:** Focus initial launch on **digital passes** for prepaid & broadband services (enable savings)
- **Perks (coupons) deferred** to future release — secondary priority
- **IMPORTANT:** Jayesh must still architect backend to support future coupon functionality **with minimal friction**
- Mark's framing: business focus = digital passes today, but don't block coupons technically

### 6. Business Logic Confirmation Needed
- Open question: should admin panel allow selecting specific coupons to sell, OR sell all available coupons?
- Romeo's recommendation: **limit to ~7–8 companies** initially
- Jayesh to share document detailing flow and business logic, including admin panel management features for:
  - Advertisers
  - Products (digital passes)
  - Revenue tracking

### 7. Saving Engine Logic — Updated with 2 Modes
- Updated flowchart incorporates **two types of logic:**
  - **Guest Estimate** — simplified (minimal input required)
  - **Detailed Mode** — asks for specifics (spending, insurance details, etc.)
- Now uses **tiered ARPU calculation** for baseline (per Apr 10 decision)
- Jayesh preparing and sharing updated flowchart

### 8. PayPal Integration Issue
- **Stripe not offering PayPal as approved payment method for US**
- Implies need for a **separate native PayPal integration** (reverts Apr 17's decision)
- Mark to investigate Stripe settings again to identify the blocker

### 9. Simplified Landing Page — Maximize Click-Through
- **Initial landing page input reduced** to just:
  - Number of lines
  - Wireless provider
  - Internet provider
- Previously asked-for fields (like amount paid) now captured **incrementally** within savings dashboard tiles
- Users only input info relevant to the service they are interested in
- Martin agrees with approach but wants to review full updated flowchart before finalizing

### 10. GitHub Repository for Flows
- Finalized flows (membership + saving engine) to be stored in **GitHub repository**
- Jayesh committed to uploading once finalized
