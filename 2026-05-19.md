## Topics Discussed

### 1. Notifications & Copywriting
- Mark requested help with reviewing notifications
- Jayesh offered to share content to facilitate copyrighting
- Mark to review: system generates much of the info, but needs to ensure **final output remains on brand**

### 2. Six-Line Plan Support — Validated as Requirement
- Jayesh raised: system currently only supports plans **up to 5 lines**
- Mark shared: potential new team member needs 7-line coverage (large family) → confirms 6-line capability is a valid requirement
- **Resolution:** Jayesh just needs to input this data into the database
- _(slight pivot from earlier "6+ = lead capture form" decision — now actually supporting up to 6 lines in engine)_

### 3. User Flow & Data Persistence — "Force Refresh / Start Fresh"
- Discussed UX when user submits new savings info
- **Decision:** implement **"force refresh" / "start fresh" feature**
- Logic:
  - User switches carriers (e.g., AT&T → Boost) → system retains previous info unless user **specifically resets**
  - If system detects user is already on recommended plan → provides that context
- Gives users control: reset OR view current savings

### 4. Testing & Staging Environment — Code Push Needed
- **Bug report from Romeo:** seeing "already saving" notifications when testing 1 line on AT&T
- Mark + Jayesh diagnosis: Romeo was likely looking at an **older version** of the site
- **Latest code not yet pushed to staging**
- Jayesh committed to **pushing all completed developments to staging** for accurate testing

### 5. Testing Scope — Wireless + Internet Only
- Romeo proposed systematic testing: every combination of 1–6 lines × major carriers × broadband providers
- **Mark's framing:** test specific use cases (mobile + internet savings), not random scenarios
- **Decision:** Testing scope **restricted to wireless and internet** (streaming NOT in scope for current test cycle)

### 6. UI/UX — Per-Line Pricing Display
- **Romeo's suggestion:** show **per-line pricing** (e.g., "$15 per line") instead of total monthly costs
- Reason: total bill numbers can cause **"sticker shock in reverse"** (looks too high; user thinks it's not a deal)
- _(opposite framing of Apr 27 V2 "sticker shock $10K" idea — context-appropriate)_

### 7. UI/UX — "Recommended Plan" Indicator
- Add a **"recommended plan"** indicator
- Helps users identify the best option among multiple alternatives
- Mark: copy changes handled in **Figma** → Jayesh can focus on functionality

### 8. Dynamic Updates & Promotion Tracking
- Alexander asked: how does site track promotions in real-time for services like YouTube TV / Sling TV?
- Jayesh: current MVP does **NOT scrape websites for live data**
- Uses **static suggestions** from management backend instead
- Romeo confirmed: **scraping capabilities NOT in V1**
- _(consistent with Apr 24 "manual default" decision)_

### 9. Internet Savings Baseline — Needs Adjustment ⚠️
- Romeo: internet savings calculations are **incorrect** — baseline doesn't reflect average US costs
- Jayesh: system relies on baseline provided by **Martin** for estimates (no specific user spending data)
- **Romeo's suggestion:** use **average internet price of $81** to improve accuracy
- **Status:** Mark agrees they need to finalize the correct baseline → action item

### 10. Feedback Collection System — Already Built ✅
- Alexander proposed: build questionnaire for friends-and-family round
- **Mark + Jayesh:** this feature is **already pre-built as a separate application**
- Users can submit feedback directly from the dashboard
- _(this is the SaaS feedback platform Jayesh demoed on Apr 28)_

### 11. Copy Editing Process — PDF Markup on Plane
- Mark + Jayesh discussed workflow for copy changes
- Provide Romeo with **PDFs** to mark up manually while traveling
- Mark: productive activity for Romeo's **upcoming flight**

### 12. Standardized Testing Harness
- Mark to create **testing harness in a spreadsheet**
- Goal: consistent and organized testing
- Jayesh will identify what's ready to test in staging
- Team will follow documented cases to validate functionality
- Alexander expressed interest in participating
