# 2026-04-01 — Reyly Team Meeting

## Attendees

## Topics Discussed

### 1. SL3 Plan Flow — "Switch to Cheaper Plan Within Same Provider"
- SL3 suggests users switch to a cheaper plan with the same coverage within their existing provider
- Flow: user goes to **Account → Plan settings** on provider's platform
- Reyly cannot track this change automatically
- **User must manually mark completion** to recognize the savings
- Personalization: users can click "edit" to modify provider, lines, spending

### 2. Maximum Savings Plan — Switch Provider Flow
- Design suggests switching to a different provider for max savings
- User hits "Start My Saving" → shown instructions to switch
- Requires: phone number, account number, zip code
- Data source: Reyly DB has normalized data for unlimited talk/text, GB per line
- NOT available: megabytes-per-second speed per line
- Plan info can display dynamically based on available data points

### 3. Account Number & PIN Collection Concerns
- Open concern: are we permitted to ask users for account number at this stage?
- Jayesh clarified: Romeo provided Excel file with **guide** on how users can find account number per provider
- **Consensus:** treat account number as part of a **preparation guide**, not something Reyly stores
- Mark suggested: capture ephemerally to improve UX — needs discussion with Romeo re: FCC regulations
- Same concern applies to PIN numbers

### 4. Paywall + PIN Collection Sequencing
- Flow: Start free trial → credit card info → **then** asked for PIN
- If user doesn't have PIN → popup guides retrieval → on entry → redirect to Flex Offer for switch

### 5. Internal Customer Service Redirection
- **Decision:** add "Call customer service" option at bottom of PIN retrieval popup
- Reason: users without digital apps (e.g., Verizon app) need paper bill assistance
- Initial concern: direct calls to providers like Mint lose affiliate tracking
- **Solution:** redirect to **Reyly's own 800 customer service number** → walk user through process without losing affiliation

### 6. Internet Savings Flow
- Hassle-free: user just tells system they made changes (system doesn't track)
- Maximum savings: **paywall BEFORE showing switch instructions** (required sequencing)

### 7. Flex Offer Link Placement
- Flex Offers link tied directly to the specific offer
- Surfaced only after all information is collected
- Wireless flow: collect info → "Confirm your detail and start saving" → redirect to Flex Offer

### 8. Registration vs. Paid Sign-Up Distinction
- Users register first → see savings dashboard → offered membership at point of moving forward
- **Hassle-free option = free** for registered users (showing how to lower bill within existing plan)
- **Maximum savings = paid** (membership required)

### 9. Scenarios Without Savings Potential
- Two edge cases system can't offer savings:
  1. User's plan amount too low for any competitive option
  2. Only hassle-free savings possible, but not maximum savings
- Team has pre-written copy: "You're already doing great" → redirect to other categories
- Jayesh to document the second scenario explicitly

### 10. Disintermediation Concern — Plan Names Revealed Too Early
- **Mark's concern:** max savings card currently reveals specific plan name (e.g., "Verizon Large Saver Plan") BEFORE user pays for subscription
- Risk: user sees plan name → bypasses Reyly and subscribes directly → disintermediation
- Mark requested screenshot of 3 cost tabs to discuss flow with Romeo
- _(Note: this led to Apr 6 decision to not surface plan names in V1)_

### 11. TV & Streaming Flow
- Initial question: does user need new cable/satellite? (copy still being finalized)
- If "Yes" → options shown
- If "Maximum" → pay first → then show options
- Concern raised by Martin: "Start free trial" shown on streaming options, but many streaming services don't offer free trials
- **Resolution:** streaming screen = **menu of options** → user picks provider (radio button) → clicks "Start My Service" → redirected via affiliate link

### 12. Specific Package Details for Streaming
- Mark asked: can we pull specific channel details (NFL, ESPN, etc.) for each streaming package?
- Martin: unsure if this level of detail is accessible for services like YouTube

### 13. Subscription Reminder Feature (NEW)
- Allows users to set reminders for canceling services
- User flow: search provider, select popular, or create custom service reminder
- Delivery: **email + calendar event**
- **Security discussion:**
  - Martin: personal reluctance toward calendar integrations (malware insertion concerns)
  - Mark: uses calendar heavily → retain "Add to Calendar" feature (not everyone shares Martin's concern)
- **Decision:** feature is **free for all users**

### 14. Reminder Storage & Display
- Mark suggested: add reminders to user's **"wallet"** (digital savings page) for constant visibility
- Confirmed: reminders will display on digital savings page
- Savings page now has **4 boxes** (up from 3) with addition of subscriptions

### 15. Membership Price Change Policy
- Open question: if price increases ($7.99 → $12), does it apply to new only or existing too?
- **Martin's position:** apply to ALL users, but existing users **must be notified in advance** via:
  - Email
  - Dashboard popup
- Advance notice requirement locked in

### 16. Apple Login (OAuth) Follow-Up
- Jayesh waiting on Apple account for "Login with Apple" implementation
- Mark committed to setting up Apple OAuth account

### 17. Database Files Handoff
- Martin to send latest versions immediately:
  - Internet plans database
  - Wireless plans database
  - FCC zip code data
- Martin suggested scheduling follow-up to review savings calculation logic
