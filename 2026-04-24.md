# 2026-04-24 — Reyly Team Meeting

## Attendees

## Topics Discussed

### 1. Estimate Review
- Mark thanked Jayesh for sending the **time/cost estimate**
- Initial review: looks **reasonable**
- Mark to review **line by line during a flight** → provide edits/feedback later that night
- Jayesh asked to flag anything missed or skipped (especially previously planned/changed items)
- Romeo offered **optional review** of estimate (not mandatory given other commitments)

### 2. Data Acquisition — Legal Constraints on Direct Scraping
- **Direct scraping is legally restricted** — consequences possible
- Plans vary across providers (Mint, T-Mobile, etc.) → each requires unique scraping script
- Maintenance risk: breaks when site layouts change

### 3. Alternative Data Acquisition Methods Proposed
- **Option A:** Scrape an **aggregator** website (e.g., **WhistleOut**) which aggregates multiple provider plans
  - Romeo's concern: WhistleOut is private → may block scraping; update frequency unknown
- **Option B:** Use a third-party scraping provider like **Brag Data** (more secure, paid service)

### 4. No Public APIs Available
- Confirmed: **no public APIs** from providers like Mint to legally obtain plan data
- Each provider has different data structures → complex architecture; prone to breaking

### 5. FCC Data Limitations
- Romeo clarified: FCC data only shows **provider availability by zip code** for broadband
- **Does NOT include pricing information**
- Cannot serve as source of truth for pricing

### 6. AI-Powered Screenshot Reading (Manual + AI Hybrid)
- Jayesh proposed: use AI to read screenshots of plans (taken by Martin) → update database
- Concerns:
  - Manual work + AI processing cost
  - Martin warned: AI may not be exact
  - Plan details like **auto-pay discounts** are tricky to capture from screenshots

### 7. "Source of Truth" Requirement
- Mark emphasized: need a **consistent, accurate source of data** = "source of truth"
- Constraints: no official feeds, no direct provider relationships
- Martin already manually gathered plan info → **challenge is automating it**

### 8. Two-System Architecture (reinforced from Apr 22)
- Project needs **two systems:**
  1. **Total catalog** (source of truth — full provider/plan data)
  2. **Monetizable plans** (FlexOffers, Impact, etc.)
- The two should **converge** — show users what's both best AND monetizable
- WhistleOut scraping would be for **internal catalog**, NOT for displaying to customers

### 9. WhistleOut & Aggregator Partnership Research
- Team to research:
  - Data accuracy
  - Update frequency
  - Whether WhistleOut offers a professional feed or partnership
- Jayesh's concern: aggregators like WhistleOut likely won't share data — they use **affiliate links for revenue** → they're competitors

### 10. Manual Data Entry — Current Default
- **Romeo's pragmatic suggestion:** move forward with manual process for now
- Focus on **3 major providers:** AT&T, Verizon, T-Mobile
- Reason: no easy automated source exists
- **Competitor benchmark:** Wirefly appears to have a dedicated auditing team → suggests they rely on manual updates too

### 11. N8N Automation + Alert System (90% Automation Idea)
- Mark + Romeo explored using **N8N** to:
  - Monitor provider websites for plan changes
  - Create alerts when changes detected
- **"90% automated" solution:**
  - Alerts flag changes
  - Human manually verifies and updates the data
  - Builds Reyly's own self-curated catalog
- **Jayesh's concern:** modern websites use **proxy / bot detection** → may block automation agents

### 12. Data Workflow Design — Mark to Lead
- Mark committed to **designing the workflow** for data acquisition (manual or automated)
- Jayesh to review and implement once workflow is drafted
- Mark to start straw man workflow **over the weekend**

### 13. Friends & Family Release Timeline
- ✅ Authentication milestone complete
- ✅ Membership milestone complete
- Started: saving engine logic
- **F&F release estimate: ~May 15th** (with static data + all saving logics)

### 14. Mid-Tier Plan Logic Confirmed
- Martin clarified plan ordering convention:
  - **1st plan listed** = entry-level
  - **2nd plan listed** = mid-tier
  - **3rd plan listed** = premium
- Martin to send Jayesh **list of mid-tier plan names per carrier** to support savings logic

### 15. Figma Copy Edits
- Jayesh to send Figma link with draft copy to Martin
- Martin to review and execute copy edits today
