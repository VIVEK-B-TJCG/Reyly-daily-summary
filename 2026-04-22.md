# 2026-04-22 — Reyly Team Meeting

## Attendees
- Mark Gilmor
- Romeo Reyes
- Martin Lerda
- Jayesh Gohel

## Topics Discussed

### 1. Source of Truth — Price Comparison & Monetization Problem
- **Core business problem:** data inconsistency across platforms (Flex Offers, Impact, etc.)
- Need a single **"source of truth"** to direct customers to the cheapest available option, regardless of immediate monetization capability
- Martin Nory has already created a basic V1 of this source of truth
- Jayesh to estimate cost of creating the data model and application infrastructure to wrap existing components

### 2. Three-Phase Development Approach (APPROVED)
- **Phase 1 — MVP**
  - Use existing database files as temporary source of truth
  - If an affiliate link is available in Flex Offers → redirect via that link
  - If not available → still redirect, but commission may be lost
- **Phase 2 — Multi-network integration**
  - Integrate Impact and Sing alongside Flex Offers
  - Compare commissions across networks → use most lucrative affiliate link
  - Build snapshot system for provider pricing plans → notify admins of changes for manual data entry
- **Phase 3 — AI-powered automation**
  - Use AI to automatically extract plan data from images / provider websites
  - Keep human verification in the loop for approval (no longer data entry)
- Immediate framing: manage **two data systems** (catalog = source of truth; monetization = Flex/Impact) + rules governing their interaction

### 3. Membership Milestone Completion Status
- Milestone complete — demo presented
- **Apple Pay & Google Pay integrated** but require external testing (can't test from India due to location constraints)
- Sign-up flow → lands on savings landing page → "Start your free trial" button initiates subscription

### 4. Payment Flow & Vendor Name Concern
- Payment options demonstrated: card + connect bank account
- Apple Pay / Google Pay buttons not visible during demo (location constraint)
- **Concern raised:** bank account connection flow currently displays third-party vendor name "Concurrent"
  - Could deter users from completing connection
  - Jayesh confirmed: small 5–10 minute API fix to hide it

### 5. Free Trial & Membership Management
- Users pick payment method → free trial activates → monthly membership status set
- Admin panel shows: trial period status, membership status, time until trial ends and customer is charged (set to 1 day for testing)
- Last 4 digits of card visible to user and admin; full card info stored securely in Stripe

### 6. Membership Email Communication
- Trial start email includes: trial end date + automatic continuation notice
- **"Upgrade Now"** button → starts immediate paid membership → generates invoice
- Admin screen: search by name/email/mobile; filter by membership status (non-active, free trial, active)

### 7. Invoice & Audit Log Requirements
- Invoice PDF generated — placeholder data needs replacing
  - Proper organizational address
  - Business Identification Number
  - Tax numbers
- **Audit log required** for process compliance
  - Full activity timeline: when customer converted from trial → active member
  - Jayesh to ensure audit log implementation

### 8. Deep Linking Concerns — Flex Offers
- **Major concern:** deep linking is OPTIONAL in Flex Offers
- Users might land on provider **homepage** (e.g., Visible's homepage) instead of the specific deal page → degrades UX
- Martin added: if transaction occurs after non-deep-link redirect → platform may have no way to track completed deal → savings engine can't be populated
- **Proposed workaround (Jayesh):** explore generating **proprietary deep links through the Flex Offers system**

### 9. Digital Passes & Perks — Next Phase
- Open question: how to handle digital passes and perks
- Flex Offers primarily supports redirects to provider website — current "buy pass → get coupon code" model NOT feasible through Flex
- Need to determine which providers offer digital passes via Flex Offers
- **Consensus:** prioritize core engine development → then focus on digital passes/perks specifics
