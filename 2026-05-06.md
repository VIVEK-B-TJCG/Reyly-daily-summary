# 2026-05-06 — Reyly Team Meeting

## Attendees
- Mark Gilmor
- Romeo Reyes
- Martin Lerda
- Jayesh Gohel

## Topics Discussed

### 1. MVP Change Documentation — Proceeding
- Mark + Jayesh agreed to proceed with MVP change documentation
- Conversation pivoted to **database structure design**

### 2. Dual-Database Architecture (Source of Truth + Monetization)
- **Decision:** implement **two-database structure:**
  - **Primary database** = source of truth for ALL plans (including non-monetizable ones)
  - **Monetization database** = potentially incomplete, just Flex Offers + Impact data
- Flex Offers alone CANNOT serve as source of truth for all plans
- **Romeo's analogy:** like OpenTable — show service providers for credibility/goodwill even if a reservation (monetization) can't happen through the platform
- Jayesh confirmed: if affiliate/Flex offer unavailable → user still redirected to provider's platform

### 3. Carrier Selection Menu — Consolidate to 3 + Other
- **Romeo's suggestion:** reduce carrier options from 20 down to **3 visible + "Other"**
- "Other" option triggers **autofill input** for users to type their carrier
- Reason: 25 names in a menu looks bad
- Jayesh agreed (especially important for internet providers which are numerous)

### 4. Staging & Copy Audit Plan
- Staging is **up**; testing complete up to plan suggestion step
- Romeo + Martin need **screen-by-screen copy audit** of staging
- Items to address:
  - "savings" vs "saving" wording
  - Capitalization
- **Martin's preference:** perform audit using **Figma** (worked well for previous edits)

### 5. Sign-Up UX Concerns — Phone Number Requirement
- Martin's concern: requiring phone number during initial registration may hurt UX
- Suggestion: email-only sufficient before user becomes paying member
- Mark's counter: phone number is **commonly used for MFA** (multi-factor authentication)
- Acknowledged: need consistent assumption set so Jayesh can build against it
- _(decision deferred, but noted)_

### 6. Remove Redundant "Improve Savings" Option
- **Issue:** users on already-optimized lower-cost plans (e.g., Mint Mobile) still see "Improve savings" option
- Clicking it surfaces a cheaper plan OR national coverage option — redundant
- Jayesh: wording "Improve savings" might be confusing → could rename to "**personalize my saving**" (allowing users to re-edit info)
- **Decision:** remove "Improve savings" option for cheaper carriers

### 7. "Cheaper Plan" Priority Option — REMOVED Entirely
- Romeo questioned why "cheaper" is even a priority option (should be the default!)
- Romeo's proposed two primary options: **"Better Network"** and **"New Phone"**
- Jayesh: "new phone" was already **postponed for V1** (per Apr 23 decision)
- Jayesh confirmed: "cheaper plan" option currently makes no sense — recommended plans are already cheapest in their carriers
- **Decision:** remove "Cheaper Plan" priority option entirely

### 8. Handling Users Without Internet Needs
- **Use case raised by Martin:** users who don't need to save on internet (e.g., internet included in rent)
- **Jayesh's initial proposal:** move internet provider input inside savings dashboard page
- **Romeo's counter:** default assumption should be user HAS internet → use a **toggle / negative option**: "I don't need internet"
- **Decision:** go with the negative-option (toggle) approach

### 9. Internet Provider Selection — Top 3 + "I Don't Need Any"
- Jayesh: show top 3 internet providers + 4th option "I don't need any"
- Romeo supported
- **Martin's flag:** the banner "save up to $800 a year" doesn't make sense for users without internet → must be hidden
- Same for SL3 option — shouldn't surface for users without internet bill

### 10. Maximum Savings Recalculation Logic — Complex Case
- **Scenario from Jayesh:**
  - User initially evaluated against **mid-tier price** (e.g., $65/month)
  - User switches to a cheaper plan (e.g., $45/month) and marks it as **done**
  - **Question:** should max savings recalculate using $45 actual, or stick to $65 mid-tier?
- **Martin's position:** once **exact spending data point is available**, engine should use the actual number, NOT the mid-tier default

### 11. Recalculation + Slider Input — Edge Case
- After initial recalculation, if user personalizes via slider:
  - **Slider value > exact plan price** — use the slider amount? (Martin says yes — use slider when provided)
- **Jayesh's nuance:** if customer marks switch as complete → exact known → savings change. But if they then use the slider again, system would need to **revert to mid-tier logic**
- **Action:** Jayesh to document this logic problem via email to Mark + Romeo

### 12. "Better Coverage" Option Placement
- Martin suggested potentially moving "better coverage" into the section with other options
- Reason: priority options are somewhat irrelevant since system no longer asks for user's zip code
- _(wait — but May 12 confirmed zip code IS used for plan suggestions; revisit)_
- Martin to add this suggestion to email going to Romeo

### 13. Wallet Feature — Pending Work
- Jayesh: will address wallet feature when starting that work
- Underlying logic is working as planned (just UX concerns)

Jayesh Gohil noted that the wording "Improve savings" might be confusing and could potentially be replaced with something like "personalize my saving," allowing users to re-edit potentially incorrect information they shared. Mark Gilmor and Martin Lerda agreed to remove the "Improve savings" option for cheaper options (00:11:57).
- **Discussion on Savings Options and Priorities:** Romeo Reyes questioned why "cheaper" is an option, suggesting it should be a default, and proposed the two primary options should be "better network" and "new phone" (00:12:49). Jayesh Gohil clarified that the "new phone" option was postponed for V1 implementation (00:13:42). Jayesh Gohil also stated that the "cheaper plan" option currently makes no sense because the recommended plans are already the cheapest options within their respective carriers. Mark Gilmor agreed to remove the "cheaper plan" option (00:14:50).
- **Handling Users Without Internet Provider Needs:** Martin Lerda raised the use case of users who do not need to save on an internet provider, such as those with internet included in their rent (00:14:50). Jayesh Gohil proposed moving the collection of internet provider information inside the savings dashboard page (00:15:41). Romeo Reyes countered by suggesting the default assumption should be that a user needs internet, and instead, a negative option or toggle should be provided for users to indicate "I don't need internet". Martin Lerda and Mark Gilmor agreed that the negative option approach is correct (00:16:45).
- **Refining Internet Provider Selection and Display Logic:** Jayesh Gohil suggested including three main providers for internet service and a fourth option: "I don't need any," which Romeo Reyes supported (00:17:34). Martin Lerda pointed out that the banner claiming users can "save up to $800 a year" does not make sense for users who do not pay for internet, suggesting that the saving figure and the SL3 option should not be surfaced for such edge cases. Jayesh Gohil agreed that the logic should be adjusted so the savings figure and the SL3 option are not shown if a user does not have an internet bill (00:19:08).

They inquired whether the maximum savings should be recalculated using the new exact plan price of $45/month, or if the calculation should stick to the mid-tier price for the maximum savings engine (00:23:32). - **Post-Recalculation and Slider Input Logic:** Jayesh Gohil noted that if a user personalizes their savings via the slider after the initial recalculation, the logic needs to determine whether to stick to the new exact plan price (e.g., $45) or the new slider input. Martin Lerda stated that the engine should use the slider amount when provided (00:26:37). Jayesh Gohil confirmed that if the customer marks a plan switch as complete, the exact plan price is known and savings change, but if they then use the slider again, the system would need to revert to the mid-tier logic (00:27:59). Jayesh Gohil requested that Mark Gilmor and Martin Lerda consider this complex logic and committed to documenting the problem via email (00:29:01).
- **Status of Priority Options and Wallet Feature:** The group agreed to proceed with getting rid of the "cheaper plan" option (00:29:01). Martin Lerda suggested potentially moving the "better coverage" option into the section with other options, noting that the current priority options are somewhat irrelevant since the system no longer asks for the user's zip code (00:30:09). Martin Lerda committed to communicating these updates to Romeo Reyes. Jayesh Gohil confirmed they will address the wallet feature when they start working on it, and that aside from the user experience concerns, the underlying logic is working as planned (00:31:17).
