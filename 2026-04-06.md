## 🟣 SESSION 1 — V1 Engine Logic & ARPU Calculation

### Attendees
- Mark Gilmor
- Romeo Reyes
- Martin Lerda
- Jayesh Gohel

### Topics Discussed

#### 1. Input Review and Excel Database Connection
- Reviewed document presented by Jayesh to align on logic and inputs
- Engine reads providers from Excel database (v6.1)
- Inputs:
  - Number of lines (up to "six plus")
  - Monthly spend ($0 to $400 in $10 steps)
- Most plans cover up to 5 lines
- **"Six plus" lines → bypass engine logic → trigger lead capture form for custom plan**

#### 2. Total Spend Calculation — Backing Out Handset Cost
- Monthly spend includes both service AND device installment payments
- Example: $300 for 4 lines = $200 service + $100 handset installment
- **Decision:** engine must back out **$25 per line** as estimated handset cost to isolate service cost
- Example flow: $300 total for 4 lines → subtract $100 (4 × $25) → $200 service cost

#### 3. V1 Strategy — No Plan Names, ARPU-Based Savings
- **Decision:** For V1, do NOT surface the exact plan name to avoid credibility issues
  - Reason: plan name might be wrong, hurting user trust
  - Most customers don't know their specific plan name anyway
- Instead, the system will:
  - Surface the current provider
  - Present potential savings by showing approximate current spend (service + phone) vs. best plan found
- **Calculation will rely on publicly disclosed ARPU (Average Revenue Per User) data**

#### 4. Savings Calculation Formula
```
Delta = Current ARPU (A) − Proposed Cost per Line (B)
Monthly Savings = Delta × Number of Lines
Annual Savings = Monthly Savings × 12
```
- Simplified for internet service (no "number of lines" variable)

#### 5. Logic for Six Plus Lines
- "Six plus" lines → surface lead capture window on wireless dashboard
- User informed a custom plan will be prepared by the team

#### 6. Data Plan Filter — Unlimited Only
- **Decision:** Filter database to only compare **"unlimited to unlimited"** data plans
- Reason: vast majority of users are on unlimited — simplifies engine logic

#### 7. Tiebreakers and Carrier Ranking
- When multiple cost-saving options match, a tiebreaker is needed
- **Tiebreaker rule:** prioritize prepaid options running on user's current primary network
  - Example: T-Mobile user → surface Mint Mobile (runs on T-Mobile network)
- Jayesh to develop admin management tool supporting:
  - Excel sheet uploads
  - Manual editing of the database
  - Data updated monthly

#### 8. Internet Service Logic
- User's self-reported input taken **at face value** — no adjustments
- If cheaper plan available → show it
- If no cheaper plan → show static content + DIY kit
- Search filter for internet maximum plans = **"fixed wireless" technology type only**

#### 9. Streaming Logic
- Streaming card shown only if user indicates they are subscribed
- **Enhancement by Jayesh:** even if user says "no" initially, streaming card offered later with option to start calculation

#### 10. ARPU Data & Postpaid Focus
- Martin to compile and send recent ARPU data for engine calculations
- **Decision:** Engine uses **postpaid ARPU only** for calculations
  - System does not differentiate user's postpaid/prepaid status based on input

#### 11. User Input as Sanity Check (V1)
- User's self-reported spend = **sanity check**, not a primary calculation input
- If user's reported spend is already low (e.g., $100 for 4 lines vs. public ARPU avg)
  - Engine concludes user is already saving
  - Avoid making potentially incorrect suggestions
- **No savings → show message:** "You are already saving"

### Decisions Made (Session 1)

|----------|--------|-------|
| Back out $25/line as handset cost to isolate service cost | Users can't easily separate service vs. device costs | Team |
